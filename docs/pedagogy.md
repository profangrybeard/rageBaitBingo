# Pedagogy

Why Rage Bait Bingo works as a lesson, and how the debrief runs.

## The idea

Students first meeting game design almost always blame the rulebook when a game frustrates them. "The directions were badly written" is the default complaint. This game takes that excuse away. Every rule is written clearly. The game is still broken. The only thing left to blame is the system, and the debrief gives them the words to name it.

## The ten tools

From Sharp and Macklin, *Games, Design and Play*, Chapter 2, "Basic Game Design Tools." These are the tools the lecture sheet, the instructor key, and every patch map to.

1. Constraint
2. Direct actions
3. Goals
4. Challenge
5. Skill, strategy, chance, and uncertainty
6. Decision-making and feedback
7. Abstraction
8. Theme
9. Storytelling
10. Context of play

If a future edition of the book renames or reorders these, update this list, the lecture sheet, and the instructor key together.

## Ignored, broken, mocked

The lecture sheet tags every example three ways.

- **Ignored.** The base game never uses the tool at all. Bingo has no challenge and no real decisions.
- **Broken.** A rule actively sabotages the tool. Cooldown takes away the only verb.
- **Mocked.** The game jokes about the tool. Premium Skip turns skill into flattering the Caller.

Every tool is hit at least twice across the cards, the patches, the Caller's behavior, and the ending. The patches are not the only designed failure. The cards, the column heads, the "patch 1.0" line, the house moves, and the House card ending are all part of the lesson.

## The one tool that works

Theme. Every rule fits the joke of a live game patched by people who don't play it. Version numbers, rollbacks, lag, premium tiers, install codes. Because theme and mechanics line up, the rage reads as intentional. This is worth saying out loud in the debrief. Ask: how long would theme alone have kept you playing?

## Running the debrief

Play first, teach second. Do not frame the ten tools before play. Tell the room only that they are playtesters for a live game, and anything that feels wrong should be reported.

After the House card wins, teach the ten tools using the room's own complaints as the examples. Whatever made them angry is on the lecture sheet.

Then each table names three problems. For each: what happened, which tool broke, and one fix. A fix that just deletes the patch doesn't count. The fix has to address the tool. "Remove Cooldown" is not a fix. "Give players a second action so skipping a mark is a choice" is.

The closing line: every rule in this game was written clearly, and the game was still broken. Clear writing isn't design. The system is.

## Paper versus online

The online edition enforces some broken rules in software. Cooldown actually eats your tap. Provisional Evens forces circles. Rollback reverts a different set of patches for each player, so the class ends up on mismatched versions. That is its own lesson: software removes arguing about rules, and it will enforce nonsense just as reliably as sense. Worth one line in an online debrief.

## What this exercise is not

It is not a lesson about rulebook writing. It is not a lesson about cheating. The Caller's cheating exists to make context of play and feedback visible, not to teach students that games are rigged. If a debrief stalls on "the Caller was mean," steer to context of play: the room kept playing only because everyone knew it was a bit.
